# 本地分类缓存与发布恢复

桌面版复用已有的闲鱼分类推荐请求，不新增爬虫或远端服务。

- 候选分类缓存在程序旁的 `data/cache/categories.sqlite3`，默认有效期 30 分钟，最多保存 256 份查询结果。按账号和商品内容隔离，重启后可以复用。
- 缓存只保存分类名称、ID、分类路径和选择结果。账号 Cookie、原始平台响应、商品正文和图片地址不写入缓存。缓存不可用时直接请求平台。
- 页面已有选择时，重新识别只刷新候选；候选必须经用户点击才能替换当前选择。第一次识别可以填入空选择。账号、标题、封面或选择版本发生变化后，旧异步结果会被丢弃。
- 真正发布前沿用原有的推荐请求核对当前类目及标签。缓存中的 ID 不能替代发布前核对。catId/channelCatId 完全一致就是同一类目，显示路径变化时直接沿用；同类目仅 ID 更新时按名称与路径确认；类目消失、更名或存在歧义时，返回最新候选供选择。
- 本地分类目录只有显示用的节点 ID，没有平台 catId/channelCatId。选中这类分类时页面会立即提示并阻止发布，不再先请求平台、再收到一句难以处理的拒绝，而是引导改用「重新识别分类」。
- 拒绝文案按原因区分：缺少平台类目 ID（本地目录或旧草稿）、没有拿到最新候选（账号登录或网络异常）、候选里找不到该分类（已消失、更名或路径变化）。
- 平台明确拒绝类目后，清除当前账号的分类缓存，并刷新一次候选。不会自动再次发布。点击新候选会保留商品内容、返回编辑，并在下次确认发布时创建新请求。
- 超时、缺少成功商品标识等结果未知的情况不会触发重新发布。本地状态修复也不会重新调用平台发布接口。

缓存是可丢弃数据，不修改主业务数据库的迁移版本。后台刷新只在软件运行期间执行。平台接口本身发生变化时，仍需要维护响应解析和请求适配。
