# 飞书通知与测试状态修复（2026-10-31）

## 原因

实际工作区的飞书 Webhook 已保存且未启用签名。电脑代理的 DNS 将 `open.feishu.cn` 返回为 `198.18.*` 合成地址，原来的公网地址校验在 HTTP 发送前就拒绝该地址。通知发送器捕获异常后丢失了“尚未发送”的证据，测试协调器因此将 Attempt #1 记为 unknown，后续核对只返回原状态。

代码检查还发现签名参数位置不正确：飞书要求 `timestamp`、`sign` 放入 JSON 请求体。详见[飞书自定义机器人官方说明](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

## 修改

- 桌面版的飞书发送器可以明确选择兼容代理的 `198.18.0.0/15` 合成 DNS；只允许 `https://open.feishu.cn:443`。其他域名、图片、通用 Webhook、服务端模式及回环/普通内网地址仍使用原拦截规则。连接继续固定到已校验地址，保留 Host、TLS SNI 和证书验证，不接受重定向。
- 地址校验及连接阶段的失败用独立异常标记为“尚未发送”，允许用户修复后以原测试记录重试。读取回执超时等不确定结果仍保留 unknown，禁止自动重发。
- 飞书签名放进 JSON，兼容历史 `StatusCode` 回执，优先采用现代 `code` 字段；失败回执保留服务方数字错误码。
- 新增只读状态接口 `POST /api/notifications/test/attempts/{id}/status`，校验本机用户、渠道及原始幂等键；查询不调用发送器。页面加载/切换渠道时核对旧记录，已关闭或已完成记录可安全清除浏览器暂存。
- 页面使用中文状态标签，显示具体错误；通知测试由本页处理异常，避免全局错误条附加“刷新重试”而误导用户。测试请求超时为 65 秒，覆盖发送器的 60 秒上限。

## 实际验证

使用用户原有飞书配置，通过修复后的原业务路由和实际 SQLite 工作区验证。用户明确确认旧测试未收到后，按原核对接口关闭 Attempt #1；随后发送一次“闲鱼助手·飞书修复测试”（验证编号 `notify-fix-20261031`）。飞书返回 HTTP 200，Attempt #2 为 confirmed、success=true、logPersisted=true、耗时 541 ms。重复同一编号返回 repeated=true，实际服务方调用仍只有一次。用户已确认收到该测试消息。
