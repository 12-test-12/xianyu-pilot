# 托盘退出后进程残留修复

日期：2026-10-31。

## 原因

实机日志显示后端已记录 `Application shutdown complete` 和 `Finished server process`，但主程序及 Chromium 子进程仍存在。只读线程采样确认后端线程已经结束，主线程仍停在 Qt 事件循环。

`ConsoleWindow.closeEvent()` 原先无条件 `event.ignore()`，用于将普通关闭操作转为隐藏到托盘。Qt 执行 `QApplication.quit()` 时也会尝试关闭隐藏窗口，因此主动退出同样被拒绝。此时退出定时器已停止，程序一直显示“正在安全退出”，Chromium 与单文件启动器也无法正常结束。

## 修改

窗口关闭事件先检查 `controller.exiting`：主动退出时接受关闭，允许 Qt 事件循环结束；普通点击窗口关闭按钮仍隐藏到托盘。保留原有先停止后台和 SQLite、再退出界面的顺序，不增加强制结束程序的逻辑。

## 验证

- 新增真正进入 Qt 事件循环的托盘退出回归；修复前必须靠 2.5 秒测试看门狗退出，修复后正常结束。
- 安装项目固定的 PySide6 6.12.0 后，7 项原生 Qt 回归全部通过。
- 在隔离目录及端口 19182 启动真实后端与离屏 Chromium，加载原控制台后执行退出。后端线程与整个 Python 进程正常结束，耗时约 9.6 秒（包含启动和页面加载），未留下该测试的浏览器子进程。系统托盘可用性在此验证中模拟，不替代冻结 EXE 的实机验证。
- 旧版本当前残留进程在确认后端已关闭后单独清理；这只是本次现场恢复，修复本身不依赖强制结束进程。

当前安装目录中的旧 EXE 未被替换，需要从包含本修复的源码重新打包后，才能获得修复后的退出行为。
