# 本地发货插件设计 · 球球助力

> 讨论稿 · 2026-11-10 更新。描述拟新增功能，供确认产品方案。

当前开发版本已接入首页「查看插件」和左侧「系统 → 插件管理」，支持独立包的发现、本地安装、启停、卸载和指令预演。球球助力预演版在插件管理页运行，商品绑定、真实 QQ 收发和自动发货按下文方案继续实施。

## 1. 要做成什么

卖家在闲鱼助手里选定商品，为它启用「球球助力」插件并保存规则。后续买家付款并提供有效参数后，软件自动联系视频里的那个 QQ 机器人，核对处理结果，回发买家并确认闲鱼发货。正常订单无需卖家逐单操作。

首版对接一个由卖家明确绑定的机器人。「球球助力」由项目维护者独立发布和更新，卖家按需安装。Windows 便携版提供插件管理、插件目录和运行接口。安装、订单处理、规则配置和执行记录都在卖家电脑上。卖家无需自建服务器，闲鱼和 QQ 通信仍需联网。

## 2. 卖家怎么设置

1. 在首页左侧「系统 → 插件管理」的「可用插件」查看「球球助力」的用途和安装要求。拿到插件包后点「从本地安装」，安装并启用插件。
2. 在「设置 → QQ 集成」连接自己的 QQ 账号，绑定视频里的机器人，检查连接状态。多个商品可以使用同一连接。
3. 在「自动发货 → 商品配置 → 发货方式」选择「插件发货 → 球球助力」。在商品规则里选择接受的参数类型，填写缺参提示和成功后的回发话术。每笔订单只走该商品选定的发货方式。
4. 可粘贴一条样例买家消息预演，查看提取到的参数、预计使用的分支和指令，以及回执判定规则。预演只展示结果。商品规则默认关闭，由卖家按商品开启。
5. 在「发货记录」查看订单当前处理到哪一步，以及结果或异常原因。

插件可以直接用内置模板，也可以复制为自定义模板。表单开放参数类型和提取规则、查询和助力指令格式、回执字段、缺参提示及交付话术。可配置的步骤限定为读取订单参数、向绑定机器人提交指令、提取回执字段和返回处理结果。付款核验、回执归属和最终发货由主程序负责。

## 3. 怎么嵌入现有页面和便携版

- **界面。** 「插件管理」分为「可用插件」和「已安装」。可用目录显示插件名称、用途、发布者、所需连接和获取方式。沿用「自动发货」现有的商品配置弹窗，在「付款后发货」的模式下拉框增加「插件发货」，只列出已安装且启用的发货插件。卖家选中后才展开模板选择和配置区。常用项直接显示，提取规则和指令格式收在「高级设置」。模板编辑、预演和导入导出都在这个配置区完成。[现有商品发货表单](../apps/web/src/pages/AutoDeliveryPage.vue)
- **前后端分工。** 现有 Vue 前端负责渲染表单，沿用应用的输入框、选择框、开关和提示组件。后端提供插件名称、支持的字段、默认值和校验规则。导入的模板作为数据解析，页面以文本展示模板文案，保存时由本地后端再次校验。
- **程序打包。** 目录版和单文件 EXE 都提供通用插件宿主和可离线读取的目录信息。插件执行文件通过单独的包分发。收到已核验的订单后，由本地后台按插件 ID 和版本执行任务，商品弹窗只负责配置。[现有 Windows 打包入口](../packaging/windows/xianyu_portable.spec)
- **故障隔离。** 商品列表和原有文本、卡密表单独立加载，打开插件配置时再读取本机模板。QQ 离线时仍可打开并编辑本地规则。表单读取失败时，在插件配置区显示原因并保留原配置。后台仅在实际遇到缺失或不兼容的规则时，暂停相关任务。首版入口放在单商品的付款后发货配置中。已有规格规则继续按现有优先级执行，弹窗提示实际生效的范围。批量启停等现有操作保留已保存的插件参数。

## 4. 插件和配置怎么保存

| 内容 | 谁来制作 | 存放与分发 |
| --- | --- | --- |
| 「球球助力」插件包 | 项目维护者实现指令和回执规则，提供默认模板并独立发布 | 签名 ZIP 或插件文件夹。安装后放在 EXE 同级的 `plugins/<插件 ID>/<版本>/` |
| 卖家模板和商品绑定 | 卖家在界面上复制模板、改规则、选商品 | 写入 EXE 旁的 `data/app.sqlite3`。源码运行时使用项目根目录下的 `data/` |
| 订单执行记录 | 后台在创建任务及每次执行后写入 | 写入同一数据库，保存实际使用的规则快照、执行进度和回执 |
| 可分享的模板文件 | 卖家从软件导出，也可在另一台电脑导入 | 一个带格式版本的 JSON 文件，可通过微信等渠道传递 |

「从本地安装」接受 ZIP 或解压后的文件夹。主程序读取 `manifest.json`，离线校验发布者签名、插件版本和宿主兼容范围，确认后复制到插件目录。手动放进目录的包同样要经过校验和启用确认。安装、启用和按商品绑定分别操作。新版本通过导入新版包安装，主程序和插件可分别升级。通过同样校验的包即使未列在可用目录中也可以安装。[VS Code 的本地扩展包安装方式](https://code.visualstudio.com/docs/configure/extensions/extension-marketplace#_install-from-a-vsix)

商品保存时，在同一次数据库写入中记录发货模式、插件 ID、所用模板版本、商品参数、本机 QQ 连接引用和启用状态。模板编辑生成新版本。卖家保存商品规则后，新订单使用该版本。已建任务读取创建时的插件版本和规则快照。停用或卸载插件后，暂停该插件的新派发并保留商品配置与执行记录。升级后遇到程序无法执行的旧版本时，保留记录并标记待核查。

导出文件只包含文件格式版本、插件 ID、规则格式版本、模板规则和公开文案。QQ 凭据、闲鱼登录信息、订单及买家消息保存在原电脑。导入时校验文件格式、插件对该规则版本的支持情况和规则字段，通过后存为一份新草稿，卖家随后绑定自己的商品和 QQ 连接，再按商品启用。

换电脑或升级时，从托盘退出软件后备份 `plugins/` 和 `data/`。程序更新保留已安装插件、本地模板和商品绑定，跨电脑后按平台要求重新授权。日常运行时，电脑需要开机联网，闲鱼助手可以驻留托盘，闲鱼和 QQ 连接都需要在线。休眠、断网或退出期间暂停外部操作，恢复后先核对订单及已有回执，再继续处理待办。存储和迁移沿用项目现有约定。[便携版数据与升级](../README.md#数据与升级)

### 维护者发布预演版

使用已安装项目 Python 依赖的环境。在源码目录执行下列命令，先创建用于签名的密钥，再打独立插件包。已拥有签名密钥时，从打包命令开始。

```powershell
python scripts/package-desktop-plugin.py keygen D:/private/qiuqiu-plugin.key D:/private/plugin-publisher.pub
python scripts/package-desktop-plugin.py package plugin-packages/qiuqiu-assist/manifest.json D:/private/qiuqiu-plugin.key dist/qiuqiu-assist-0.1.0.zip
```

将签名公钥 `plugin-publisher.pub` 随程序放在 EXE 旁边。签名私钥留在维护者自己的目录。将 ZIP 单独提供给用户，用户可选 ZIP 或解压后的文件夹安装。源码运行时，公钥放项目根目录。预演版包只包含清单和签名，清单以 `hostApi: 1` 声明宿主接口版本。改动已发布清单时先提升插件版本。

## 5. 一笔订单怎样自动处理

1. **确认订单。** 收到付款事件或买家消息后，核实订单属于当前卖家账号和已启用插件的商品，且已付款、可履约。付款和参数可以先后到达。订单按卖家账号及平台订单号去重，创建时保存插件和商品规则的版本。
2. **收集参数。** 从本订单关联的买家会话提取有效短链接、球球号或昵称。参数缺失时自动发一次提示并等待补充。同一会话有多笔候选订单或多个互相冲突的参数时，先请买家明确订单或确认使用哪个参数。
3. **执行助力。** 有有效短链接时，向固定机器人发送「助力 + 短链接」。有球球号或昵称时，先用「查」指令查询，提取并核对**全服排名**，再发送「助力 + 排名」。球球号用于查询。遇到重名或匹配不唯一时，自动提示买家补充球球号。
4. **核对回执。** 同一 QQ 通道一次处理一笔订单。优先使用机器人引用的消息 ID、回显的请求编号，或经实测可核对的目标信息，把回执关联到本次请求。助力指令已送达、机器人已回复、助力已完成分别记录。
5. **回发并确认发货。** 确认助力达到该商品的交付条件，且订单仍可履约后，向原闲鱼会话发送结果。闲鱼消息发送确认后，再单独确认平台发货。两个步骤分别保存回执。商品配置更新后，新订单读取新版本，已建任务按保存的版本恢复。

## 6. 异常怎样处理

| 情况 | 软件行为 |
| --- | --- |
| 缺参数、昵称重名或订单归属有歧义 | 提示买家补充信息，任务等待；收到可核实的回复后自动继续 |
| QQ 掉线，且请求确认尚未发送 | 暂停提交。连接恢复并确认订单仍可履约后，按重试规则处理 |
| 助力请求可能已发出，回执超时或归属不明 | 将任务标为「待核查」并通知卖家。先核查已有记录，再决定后续操作；通道有迟到回执风险时暂停派发下一单 |
| 已回发买家，平台发货确认失败 | 单独核对平台发货状态，必要时重试确认步骤 |
| 订单退款或关闭 | 停止后续提交和发货，保留已发生操作的记录 |

## 7. 现状与启用条件

仓库已有商品规则、任务快照和 QQ 串行队列基础。当前交付的桌面版尚未接入这套外部机器人流程，QQ 工作流中的闲鱼交付和平台确认仍是模拟。现有 QQ 接收逻辑支持文本和引用，视频中的回复带头像或按钮卡片，需要用这个机器人的真实脱敏回执核实连接器能收到哪些字段。[当前桌面版交付范围](../README.md#为什么做这个桌面版) · [QQ 工作流](../apps/desktop/workflow_worker.py) · [QQ 消息接收](../apps/desktop/qq_connector.py)

以下项目通过后再开放正式自动执行。

- 验证旧数据升级后可继续打开、编辑和保存文本、卡密及规格规则。分别用目录版和单文件 EXE 验证可用目录、本地安装、拒绝签名无效或版本不兼容的包、启停、独立升级、模板导入导出及保留 `plugins/` 和 `data/` 升级。验证插件模式在模板无效、QQ 离线和保存冲突时有明确提示，重启后能回读已保存的配置。
- 用授权账号和同一个机器人跑通短链接、昵称、球球号三种输入，确认查询回执能稳定提取全服排名，助力回执能对应具体请求。
- 确认「超大助力已拉满」的业务含义。若它既可能表示本次成功，也可能表示目标原本已满，先明确商品交付条件，并取得可核对到目标的证据。单句通用提示且无归属证据时，任务进入待核查。
- 验证真实闲鱼闭环，包括付款核验、原会话回发和平台发货确认，并复测重复付款通知、迟到回复、退款、断网和重启恢复。[订单核验与双监听设计](official-order-delivery.md) · [商品规则与任务快照设计](auto-delivery-product-standard.md)

首版交付范围为主程序的插件管理和宿主、单独发布的「球球助力」插件包、商品配置表单、模板编辑与导入导出、自动执行及发货记录。后续发货插件可以沿用同一个商品入口，独立发布和更新。
